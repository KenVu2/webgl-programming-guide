On a blue canvas, a quadrilateral is drawn below with a WebGL fragment shader that calculates the pixel intensity with a sin function whose wavelength (as pixels per cycle) is controlled by the slider. The quad is 400 pixels wide.

  1. No Aliasing: Above the Nyquist limit, when Pixels Per Cycle ≥ 2, the texture renders without aliasing and looks "good".
  2. Aliasing: Below the Nyquist limit, when Pixels Per Cycle < 2, the sin functions frequency is much too high to be captured by the 400 pixel width of the quadtrilateral. Instead, the texture appears to have a frequency much lower than the mathmematical frequency ( Cycles Per Pixel ).
    This demonstrates aliasing occurring where we have "a high frequency signal masquarading as lower frequency signal."

Pixels Per Cycle: 400

Cycles Per Pixel: 400

Fragment Source Code

uniform mediump float u_pixels_per_cycle;
void main() {
// note, we normalize sin to vary from 0 to 1, and use that as intensity variation
gl_FragColor = vec4(1.0, 1.0, 1.0,1.0) * (0.5*sin( (CANVAS_WIDTH - gl_FragCoord.x)/u_pixels_per_cycle*2.0*pi)+0.5);
gl_FragColor[3]=1.0;
}
